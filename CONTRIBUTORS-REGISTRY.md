# Implementer Registry

This registry is an information exchange, not a gate.

## Read this first

- Registration is **not** a condition for downloading or using the
  specification. Not registering is fully compliant.
- Registration is voluntary. You may register with a name only and no
  contact address.
- Registering grants no trademark, certification, or permission, and it is
  not an admission step. Not registering is not an exclusion.

Basis: `OPEN-100-015` (any conforming implementation may use the protocol
name at no cost) and `OPEN-100-016` (no implementation may be excluded on
grounds of trademark, certification, or name).

## What registration gets you

1. Your implementation is listed in this registry, publicly readable.
2. You receive release and freeze notices. These are version notices only,
   never marketing.
3. You may request a cross-implementation reconciliation run.
4. A later implementation may cite your reproduction record as evidence.

## Fields

| 4 | Reproduction conclusion: A fully reproduced, B partially, C not reproduced | yes | yes |
| 5 | Link to reproduction record | optional | yes, if given |
| 6 | Willing to run reconciliation with another implementation | yes | yes |
| 7 | Public contact (mailbox or repository) | optional | your choice |
| 8 | Release-notice address | optional | no |
| 9 | Consent to be listed by name | yes | yes |
| 10 | Registration date | yes | yes |
| 11 | Withdrawal notice | yes | yes |

The registry is deliberately wider than it needs to be so that you can take
part by name alone, without handing over a mailbox.

## Privacy

- The release-notice address is used for release and freeze notices only. It
  is never used for marketing and never shared with a third party.
- Withdrawal is available at any time. On withdrawal, all records are
  deleted and no copy is retained.
- Registration must not be converted into an admission condition.
- Registered and unregistered implementations receive identical treatment.

## What we will not do

1. We will not make registration a precondition for download or use.
2. We will not refuse reconciliation, support, or equal treatment because an
   implementation is unregistered.
3. We will not promise priority or exclusivity to a registered party.
4. We will not use registry information for marketing or resale.
5. We will not require registration inside the specification.

## What this registry does not do

It does not grant any power beyond the custodian's five listed duties. It
turns "who is using this" from rumour into a public record, and nothing else.
