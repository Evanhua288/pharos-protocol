# 三、哈希与签名（**定死**）

```
哈希输入 = 前缀 ‖ UTF-8( JCS( 对象 **排除 `hash` 与 `sig`** ) )
签名输入 = UTF-8( JCS( 对象 **排除 `hash` 与 `sig`** ) )     ← 不含前缀
```

**⚠️ 三点必须同时满足**：

| # | 规则 | 条号 |
|---|---|---|
| **1** | **`sig` 必须被排除**——否则签名自引用，永远算不出来 | `CORE-001-025/027` |
| **2** | **前缀只用于哈希，不用于签名** | `CORE-001-026` |
| **3** | **`LedgerEntry` 前缀 = `ASCII(prevHash)`；其余四对象前缀 = **空字节串**** | `CORE-001-022/023/024` |

# 四、判定

| 情形 | 结论 |
|---|---|
| **`v3-absent` 与 `v3-null` 哈希不同** | ✅ **缺席与 `null` 不可混用** |
| **`amount` = `"1"`** | ✅ **合法** |
| **`amount` = `"1.0"` / `"1.00"` / `"1e3"` / `"1.5"`** | 🔴 **不合法**（`CORE-001-032/033`） |
| **`amount` = `"-0"`** | ✅ **合法**——**正则 `^-?(0\|[1-9][0-9]*)$` 允许** |
| **`v6` 带 `prevHash`** | ⚠️ **这是**反面样本**：`Settlement` **不得**含 `prevHash`（`CORE-001-024`）；**其哈希值仅用于证明"照违规样例算会得到什么"** |

**⚠️ `v6` 的用途说明**：

> ## **它**不是**合法样本。它的哈希用于检验"实现有没有错误地给 `Settlement` 加前缀"。**
> ## **→ 一个正确实现算 `v6` 时，会**忽略** `prevHash` 对哈希的贡献（按 `024`，`Settlement` 无前缀），**
> ## **但 `prevHash` 作为**字段**仍在 JCS 内容里——所以它与"缺 `prevHash`"的算值不同。**
> ## **→ 两者的差值就是 `CORE-001-024` 的可测痕迹。**
