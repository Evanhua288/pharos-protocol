## 2. ⭐ 四个归你（**本层的核心条款**）

> ## **记忆归你 ｜ 劳动归你 ｜ 结算归你 ｜ 去留归你。**

| # | 条款 | 形态 | 判据 |
|---|---|---|---|
| **`ID-100-010`** | **记忆归你** | 必须 | 记忆可回看、可导出、可携带、可**真删除** |
| **`ID-100-011`** | **劳动归你** | 必须 | 劳动记录随人**携带**，不因节点变更而消失 |
| **`ID-100-012`** | **结算归你** | 必须 | 结算记录**可导出**；**不得**因退出而扣留 |
| **`ID-100-013`** | **去留归你** | 必须 | **可随时退出；退出时数据可导出带走** |
| **`ID-100-014`** | **意义归你** | **必须** | **三观槽位（`VAL-100`）与修行路径（`PRC-*`）必须**可完整导出、可携带、可真删除****；**不得**解释为“意义由平台赋予”**；**本条为**内部结构用语****；**对外表述仍按公司侧 `O-12`——**四样＋「意义归你」作总原则、不并列成第五项****；**⏪ V1.10 去重：本行原**同条号连续出现两次**（第二条为无 `O-12` 半句的简版），**现只保留本条**（承 `CORE-001-169`）** |

| 条号 | 形态 | 条款 |
|---|---|---|
| **`ID-100-020`** | 必须 | 退出**不得**设置任何实质性障碍（不得要求额外付费、不得要求对方同意） |

| **`ID-100-023`** | 禁止 | **不得**以"违规"为由单方删除用户记录（争议须走争议入口） |

## 3. 🔴 本体三态（**本规范最缺的一块，现补齐**）

> **`ID-100-030`**
> 本体**必须**定义三态：**在世 ／ 失能 ／ 身故**，并明确各态的处置规则。

| 态 | 判定依据 | 处置规则 |
|---|---|---|
| **在世** | 默认态 | **本人自主处置**；所有设置**可修改、可撤销** |
| **失能** | **须由具备法定效力的文件或指定程序认定** | 按**事先设定的托付**执行；**须有指定受托人**；受托人权限**仅限**维持既有关系与劳动 |
| **身故** | **须由具备法定效力的文件认定** | 按**事先设定的传承**执行；**须有继承人确认** |

### 3.1 三条纪律

| 条号 | 形态 | 条款 |
|---|---|---|
| **`ID-100-031`** | 必须 | 失能与身故的认定**必须**基于具备法定效力的文件或程序；**不得**由系统单方推定 |
| **`ID-100-032`** | 禁止 | 任何一态**不得**被表述为实现为"**人格延续**""**数字永生**" |
| **`ID-100-033`** | 必须 | **交接的是档案与关系，不是人格的延续** |
| **`ID-100-034`** | 必须 | **继承的是"记录"，不是"义务"**；下一代**可以**清空重填 |

### 3.2 三态的默认值（**未设定时**）

| 态 | 默认行为 |
|---|---|
| **在世** | 正常 |
| **失能（未设定托付）** | **冻结**——不删除、不转移、不公开 |
| **身故（未设定传承）** | **封存**——仅供法定继承人依当地法律申请查阅 |

> **`ID-100-036`（必须）** 用户**必须**可在世时指定：**身后是否禁言、是否关闭回看、名字是否可显示**。**未指定时默认：禁言、关闭回看、名字不显示。**
>
> **`ID-100-037`（必须）** 临时冻结**不得**阻断丧葬抚恤类支出；**冻结期间是否计入成员名册与表决基数，必须事先公示**。

**⚠️ 并一条**：

> **`ID-100-035`：未设定时不得由平台自行决定去向——**宁可冻结，不可代决**。**

## 4. 数据边界（**数据归你层**）

| 条号 | 形态 | 条款 |
|---|---|---|
| **`ID-100-040`** | 必须 | 用户数据**必须**留在本节点；**归属归用户**（**⏪ V1.10 补例外口径**：**本条的“默认驻留”不排除三种例外**：**① 用户主动迁移**（承 `ID-100-051`）；**② 节点退出**（承 `ID-100-022`）；**③ 受信任托付人代为处置的失能与身故情形**（承 `§三`）**；**除此三种外，不得将用户数据移出本节点**）** |
| **`ID-100-041`** | 必须 | 跨境**只可**传输**哈希与去标识化特征**；**不得**传输原始数据（**⏪ V1.1 优先级声明**，承 `CORE-001-176`：**跨境情形下，**本条与 `VAL-400-005` 同时适用时，**以 `VAL-400-005`（**红线**）为准**——**即：跨境须不得传原始数据，而不论是否密文**）** |
| **`ID-100-042`** | 必须 | 导出须**完整**、**可读**、**可迁移** |
| **`ID-100-043`** | 必须 | 删除**必须**在设备端生效；**不得**保留影子副本 |
| **`ID-100-044`** | 禁止 | **不得**以"隐私"为由削减必要的留存——**留存义务与归属权是两件事** |

**一致性测试 T-ID-2**：抓包零明文；删除演练通过；导出完整。

## 4A. 功能状态三态（**本版重写）**

> **⚠️ 本节因评审本次评审指出"两套三态并存"而重写。**
> **它们不冲突——是两个层，而本规范此前把两层各自写成了"唯一三态"。**

### 4A.0 两层三态的关系（**本版新增**）

| 层 | 名称 | 管什么 | 条号 |
|---|---|---|---|
| **第一层 · 法律状态** | **在世 ／ 失能 ／ 身故** | **一个人在**法律上**处于什么状态** | **`ID-100-030`** |
| **第二层 · 功能状态** | **活跃 ／ 静默 ／ 交托** | **本体在**系统上**处于什么状态** | **`ID-100-060`** |

**映射表**：

| 法律状态 | 对应的功能状态 | 说明 |
|---|---|---|
| **在世** | **活跃**（默认） | **本人在场，本体可操作** |
| **在世** | **静默** | **本人长期不活跃；本体只读** |
| **失能** | **静默 或 交托** | **由事先设定的托付决定；未设定时为静默** |
| **身故** | **交托** | **本体转只读档案** |

| 条号 | 形态 | 条款 |
|---|---|---|
| **`ID-100-065`** | **必须** | **法律状态决定功能状态的可选范围；不得由功能状态反推法律状态** |
| **`ID-100-066`** | **必须** | **失能与身故的认定只能由具备法定效力的文件或程序作出**（**承 `ID-100-031`**）；**系统不得因"长期不活跃"而推定失能** |

**转移表**：

| 从 | 到 | 触发 | 谁可发起 |
|---|---|---|---|
| **活跃** | **静默** | **本人长期不活跃**（**连续 180 日**） | **本人或系统提示**（**须本人确认**） |（**⏪ V1.39 填值**：原为空；**未确认前不转静默**）
| **静默** | **活跃** | **本人回来** | **本人** |
| **活跃／静默** | **交托** | **身故**（法定文件） | **法定程序** |
| **活跃** | **交托** | **本人明示交出** | **本人** |
| **交托** | — | **不可逆** | — |

**⚠️ `ID-100-067`（必须）**：**交托态不可逆；若出现认定错误，只能由法定程序更正。**

> **背景**：**此设计原在早期件（“权限与只读概念”），始终未进协议。**

| 态 | 名称 | 什么意思 |
|---|---|---|
| **一** | **活跃** | **本人在场，本体可被操作** |
| **二** | **静默** | **本人长期不活跃；本体只读，不再产生新记录** |
| **三** | **交托** | **本人身故或明示交出；权限与只读概念生效** |

| 条号 | 形态 | 条款 |
|---|---|---|
| **`ID-100-060`** | 必须 | **本体**功能状态**必须有三态（活跃／静默／交托）；**与 `ID-100-030` 的**法律状态**并存，按 §4A.0 映射** |
| **`ID-100-061`** | 必须 | **交托态后，本体转**只读档案**；**不模拟人格、不代答、不推演** |
| **`ID-100-062`** | 必须 | **情感类内容**默认遮蔽**；**非本人不可读** |
| **`ID-100-063`** | 必须 | **记录**全部可导出**；导出格式必须可被带走** |
| **`ID-100-064`** | 禁止 | **不得把交托态用于展示、宣传或纪念性营销** |

**一致性测试 T-ID-5**：交托态本体无新记录产生；非本人无法读取情感类内容；导出完整。

## 5. 记忆的规范

| 条号 | 形态 | 条款 |
|---|---|---|
| **`ID-100-050`** | 必须 | 记忆**必须**可回看；**不得**仅写入不可读 |
| **`ID-100-051`** | 必须 | 记忆**必须**可携带——跨节点迁移**不丢**（**⏪ V1.10 限定**：**本条只管**完整性**（迁移后不丢），**不授权**跨境传输**；**跨境情形另按 `ID-100-041` 与 `VAL-400-005`**（**红线））** |
| **`ID-100-052`** | 必须 | 记忆**必须**可真删除（走同一机制，不留副本） |
| **`ID-100-053`** | 禁止 | **不得**保留用户不可见的"影子档案" |

## 6. 与相邻层的关系

| 相邻层 | 关系 |
|---|---|
| **L0 物理（PHY）** | 节点退出时，用户数据按本层规则导出 |
| **L2 社区（COM）** | 社区**不得**扣留成员数据 |
| **L5 认知（COG）** | 认知记录删除**走本层同一机制** |
| **L6 修行（PRC）** | 传承交接**承接本层三态** |
| **L7 意义（VAL）** | 三观与贡献记录**必须**可导出、可携带、可真删 |
