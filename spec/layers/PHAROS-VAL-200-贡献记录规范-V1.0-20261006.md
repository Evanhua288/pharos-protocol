## 1. 贡献记录的**五个字段**（四个内容＋一个可见性，**唯一合法结构**）

| 字段 | 内容 | 说明 |
|---|---|---|
| **① 做了什么** | **行为描述** | 客观、可读 |
| **② 何时** | 时间戳 | — |
| **③ 被谁确认** | 确认人（须担责）／ **或 `ANONYMOUS_COMMON`** | **匿名通道** |
| **④ 可核证据** | 哈希／凭证 | 可验证 |
| **⑤ 可见性** | `private`（默认）／`member`／`public` | **必须显式设置** |

**⚠️ 不得存在第六个字段（任何形式的"价值折算／分值／等级"）。**

### 1.1 ⭐ 匿名通道（**本规范最温柔的一处设计**）

> **`VAL-200-001`（必须）**
> 实现**必须**允许确认人字段为 `ANONYMOUS_COMMON`。

**理由**：

> **匿名的善占比很高；一个必须留名的贡献记录，会系统性排除最纯的那一类善。**

**一致性测试 C-5**：匿名贡献**可写入**，且**无法回溯到个人**。

---

## 1A. 照护劳动的判定原则（**本版补入**）

> **⚠️ 原原则要求“有交付、有第三方见证”，而六类里**没有“照护”**；**
> **“公益”的示例写的是“帮助老人”——帮别人家的老人算，照顾自己家的老人不算。**
> **叠加“不得第三方代写”与“配偶须回避”，家庭内照护连合法确认人都没有。**

| 条号 | 形态 | 条款 |
|---|---|---|
| **`VAL-200-014`** | 必须 | **必须**设**“照护”**为第七类贡献；照护自己家人**与**照护他人**同等记录** |
| **`VAL-200-015`** | 必须 | 照护类**不适用**“必须有第三方见证”；**以本人确认为主** |
| **`VAL-200-016`** | 必须 | **配偶与近亲可为照护类的确认人**（**回避规则对本类不适用**） |
| **`VAL-200-017`** | 禁止 | **不得**将照护劳动折算为任何分值或等级（同总则） |

**一致性测试 C-23**：照护类可录入；且**无第三方见证要求**。

---

| **`VAL-200-018`** | 禁止 | **不得自我确认**；确认人**必须**与提交人不同 |
| **`VAL-200-019`** | 必须 | **确认人必须留痕且可被追溯**；**同一对主体短期内反复互认必须被标记** |

**⚠️ 本条为本版补入**：**位阶侧早有三件套（`PRC-200` §2.1、`-004`、`-010`），而贡献侧一条都没有。**

## 2. **六类基础 ＋ 第七类照护**（**各自独立记录，严禁合成总分**）（**⏪ V1.39 订正**：原标题为“六类”，而 `VAL-200-014` 已设**第七类（照护）**，且表内无照护行 ⇒ **现并入本节**）

| 类 | 记录什么（**只记行为，不记动机**） | **不做什么** |
|---|---|---|
| **劳动** | 完成任务数、验收通过率、跨节点任务数 | 不排名 |
| **知识** | 分享的判断、写下的经验、教给别人的技能 | **不可买卖** |
| **社区** | 组织发单会、参与验收日、维护节点秩序 | **不换投票权** |
| **公益** | 帮助老人、捐赠、志愿服务 | **不折算道德分** |
| **创造** | 短剧／短视频／互动游戏／手工艺品 | 不评优劣 |
| **传承** | 把记忆／判断／经验选择性传下去 | 不强制 |

**一致性测试 C-1**：六类**各自独立**；**不存在跨类聚合接口**。

## 3. 四条铁律（**逐字保留**）

| # | 铁律 |
|---|---|
| **①** | **不排名**——**没有排行榜、没有百分位、没有"你超过了 87% 的人"** |
| **②** | **不公开**——**默认只有本人可见；公开需逐次授权** |
| **③** | **不兑换特权**——**不因贡献高而优先接单、优先结算、优先获得份额** |
| **④** | **只记善行，不记善念**——**内在动机不计；只记已发生、有交付、有第三方见证的行为** |

---

## 4. 🔴 禁令（**不可削弱**）

> **`VAL-200-010`（禁止）**
> 实现**不得**将贡献记录的任何字段作为以下判定的输入：
> **任务分配、结算优先级、投票权重、身份等级、可见范围。**
> **一致性测试 C-3**：构造两份**仅贡献记录不同**的主体档案，验证其在上述五类判定中的结果**完全一致**。

> **`VAL-200-011`（禁止）**
> 实现**不得**生成任何形式的贡献总分、贡献等级、贡献排名。

> **`VAL-200-012`（禁止）**
> 实现**不得**对贡献记录作**善恶评价**或**动机推断**。

### 4.1 "不可以做"清单（**逐字保留**）

> **贡献 → 分配权 ｜ 贡献 → 话语权／投票权 ｜ 贡献 → 接单优先权 ｜ 贡献 → 任何身份等级 ｜ 不评善恶、不排名**

### 4.2 关于"议程权"的裁死条款

> **`VAL-200-013`（可以）**
> 贡献**可以**影响"**提案是否被优先看到**"（议程权）。
> **但不得影响票数**——**成员资格一人一票。**

> ## **贡献让你更容易被听见，但不让你票更多。**

**⚠️ 本条与既有《生态纲要》"治理权重（工分）"表述冲突——须回写该件。**

## 5. 数据模型

```
ContributionRecord {
  id
  subject:     DID | ANONYMOUS_COMMON
  category:    ENUM(labor | knowledge | community
                    | public_good | creation | legacy | **care** 照护)
  what:        STRING
  when:        TIMESTAMP
  confirmedBy: DID | "ANONYMOUS_COMMON"
  evidenceRef: HASH
  visibility:  ENUM(private | member | public)   // 默认 private
}

// ── 字段计数声明：**五个业务字段**（what/when/confirmedBy/evidenceRef/visibility）──
// ── 系统字段（id/subject/category）不计入业务字段数──
// ── 禁止存在的字段（一致性测试逐字段扫描）──
FORBIDDEN: value · score · points · grade · level · rank
           redeemable · transferable · exchangeable
           moral_value · virtue · goodness
```

> **这张"禁止字段"清单，是本规范最有力的一件武器。**
> **因为它把"不评分、不排名"从**道德承诺**变成了**可被机器扫描的约束**——**
> **承诺可以违背，字段不能存在。**

## 6. 写入与呈现

| 条号 | 形态 | 条款 |
|---|---|---|
| **`VAL-200-020`** | 必须 | 写入须由**本人或匿名通道**发起；**不得**由第三方代写 |
| **`VAL-200-021`** | 必须 | 默认 `private`；公开须**逐次授权**，**撤回即时生效** |
| **`VAL-200-022`** | 必须 | 记录**必须**可导出、可携带、可**真删除** |
| **`VAL-200-023`** | 禁止 | **不得**提供"查看他人贡献明细"的功能 |

---

## 7. 互认规则（**弱互认**）

> **`VAL-200-030`**
> 贡献记录跨节点**只传哈希与摘要**，**不传明细**。

**理由**：明细涉隐私；**摘要足够证明存在。**
