## 1. Profile 声明（**`COG-100` §2.2 五要件**）

| # | 要件 | 本 Profile 的内容 |
|---|---|---|
| **①** | **坐标定义** | **时间系**（真太阳时／干支／节气）为主轴 |
| **②** | **输入清单** | **见第 3 节**——**且不得来自行为画像的反推** |
| **③** | **输出三态** | **一致／偏离／冲突**——**不输出吉凶、不输出结论** |

| **⑤** | **禁语表** | **见第 6 节** |

## 2. 坐标定义（**形式化，不是信念**）

**本 Profile 采用"形式化"表述**——**因为形式化可复算、可验证；讲成"文明内核"就变成不可检验的信念。**

| 工具 | **形式化表述** | 允许的用法 |
|---|---|---|
| **阴阳** | **二元状态空间**（2 态） | 状态的二分描述（静／动、聚／散） |
| **五行** | **生克网络**（5 节点有向图） | 五种状态倾向：生 · 长 · 收 · 藏 · 化 |
| **八卦** | **3bit 状态空间**（8 态） | 八类情境结构（进退取舍） |
| **六爻** | **六阶动态序列** | 阶段推进的次序描述 |
| **干支** | **周期性时间编码** | 时间轴上的位置标记 |
| **节气** | **年度节律分点**（24 点） | 节奏参考（**不涉吉凶**） |
| **奇门** | **时空约束优化**（多变量约束） | ⚠️ **仅作方法论借喻，不作推演**（**见第 7 节**） |

**⚠️ 一条纪律**：

> **本 Profile 的所有输出必须可由上述形式化定义复算；**
> **不得**引入"直觉、感应、灵验"类不可复算的表达。

---

## 3. 输入清单（**且不得来自行为画像的反推**）

### 3.1 允许的输入

| # | 输入 | 来源 |
|---|---|---|
| **1** | **时间** | 用户所在经度的**真太阳时**（本地时区＋经度修正） |
| **2** | **地点** | 用户主动提供的**经纬度粗粒度**（**不采集精确轨迹**） |
| **3** | **用户主动填写的出生信息**（如启用） | **用户本人填写** |

### 3.2 🔴 禁止的输入

| # | 禁止 |
|---|---|
| **1** | **行为数据**（点击、停留、任务记录） |
| **2** | **记忆内容** |
| **3** | **社交关系** |
| **4** | **由行为反推的画像特征** |

**一致性测试 C-6**：坐标线输入集合 ∌ 行为数据集合。

---

## 4. 输出规范

### 4.1 只输出三态

**一致 ｜ 偏离 ｜ 冲突**——**不得输出吉凶、不得输出结论、不得输出建议。**

### 4.2 输出示例

| 态 | 合规示例 | 🔴 不合规示例 |
|---|---|---|
| **一致** | "你这段时间的记录重心偏静，与当前节律参照基本吻合" | "这段时间适合你" |
| **偏离** | "你记录偏向 X，与参照有偏离——**这是一个可以想一想的问题**" | "你该调整了" |
| **冲突** | "两条线给出不同指向" | "听哪一条更准？我告诉你" |
