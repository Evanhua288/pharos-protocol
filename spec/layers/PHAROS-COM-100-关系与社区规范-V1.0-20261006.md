## 1. 社区与节点的关系（**先划清**）

| 条号 | 形态 | 条款 |
|---|---|---|
| **`COM-100-001`** | 必须 | **社区不是法律主体**——社区议事规则**不得**用于对外签约、开票、收款 |
| **`COM-100-002`** | 必须 | **节点运营方是法律主体**——对外事务由其实体承接 |
| **`COM-100-003`** | 必须 | **社区的规则在其范围内有效；跨社区事务归协议治理入口** |

**一句话**：**社区管规则，实体担责任。**

---

## 1A. 社区定义与接入同意（**本版补入**）

> **`COM-100-050`（必须）** 本协议中的“社区”**必须**指：**一个有可辨识成员名册、有自己议事规则、且接受本协议约束的人群单元**。
> **⚠️ 不得以“一份带宽套餐的购买者”或“节点运营方”替代社区。**

| 条号 | 形态 | 条款 |
|---|---|---|
| **`COM-100-051`** | 必须 | **接入前必须完成社区同意程序**；形式由社区自选，**不得由实现方指定** |
| **`COM-100-052`** | 必须 | 同意记录须列明**受益主体**与**同意范围**，且**须留档** |
| **`COM-100-053`** | 必须 | 接入后 **12 个月内必须复查**；**失效则暂停新增服务** |

**一致性测试 T-COM-5**：同意记录可追溯；名册与同意范围可核。

## 2. ⭐ 议事规则（**本层最缺的一块，现补齐**）

### 2.1 五类事项

| 类 | 事项 | 决议方式 |
|---|---|---|
| **甲类** | **社区内公共资源使用** | 简单多数 |
| **乙类** | **社区公共池支出** | 简单多数 ＋ **公示** |
| **丙类** | **社区规则修订** | **三分之二** ＋ 公示期 |
| **丁类** | **接收新成员** | 简单多数（**须本人同意**） |
| **戊类** | **成员除名** | **三分之二** ＋ **须经争议程序** |

### 2.2 议事五步（**必须**）

```
① 提案（任何成员可提）
      ↓
② 公示（**不少于 30 日**；含提案理由）（**⏪ V1.39 填值**：原为空；**冻结前告知另依 `OPEN-100-037-J` 的 90 日异议期**，两者不同事项**）
      ↓
③ 讨论（记录留痕）
      ↓
④ 表决（按类定比例）
      ↓
⑤ 记录与执行（留痕；执行结果公示）
```

### 2.3 关键条款

| 条号 | 形态 | 条款 |
|---|---|---|
| **`COM-100-010`** | 必须 | **提案、讨论、表决、执行结果，必须全部留痕** |
| **`COM-100-011`** | 必须 | **表决记录必须可查**（**成员可查，非成员不可查**） |
| **`COM-100-012`** | 禁止 | **不得**秘密表决；**不得**在无公示的情况下决议 |
| **`COM-100-013`** | 必须 | **利害关系人必须回避** |
| **`COM-100-014`** | 必须 | **除名必须**给当事人陈述机会 |

## 3. 🔴 成员资格与表决权（**本规范裁死一处冲突**）

> ## **成员资格一人一票（政治权）。**
> ## **贡献与位阶只影响"提案是否被优先看到"（议程权），不影响票数。**

| 条号 | 形态 | 条款 |
|---|---|---|
| **`COM-100-020`** | 必须 | **表决权一人一票**；**不得**加权 |
| **`COM-100-021`** | 禁止 | **贡献不得**影响票数或表决权重 |
| **`COM-100-022`** | 禁止 | **位阶不得**影响票数或表决权重 |
| **`COM-100-023`** | 可以 | **贡献与位阶可以**影响**议程权**（提案是否被优先看到） |
| **`COM-100-024`** | 禁止 | **议程权不得**演变为表决权（不得以"优先看到"绕道影响结果） |
| **`COM-100-025`** | 禁止 | **不得**出现“治理权重”“投票权值”“票数加权”等**任何形式的加权表决机制** |
| **`COM-100-026`** | 必须 | **议程权的依据与记录必须可审计** |

**⚠️ 本条与既有《生态纲要》"治理权重（工分）"表述冲突——须回写该件。**

**一致性测试 T-COM-1**：**构造比对**——两个贡献与位阶不同的成员，其**表决权重必须相同**。

---

## 3A. 表决的本人认证（**本版补入**）

> **⚠️ 原制度把“政治权／议程权”裁得很干净，**
> **但全族没有一条规定表决如何绑定到具体本人——**
> **在共用设备的家庭里，“一人一票”会退化为“一设备一票”。**

| 条号 | 形态 | 条款 |
|---|---|---|
| **`COM-100-030`** | 必须 | 表决**必须**绑定到**具体本人**；**不得**以设备为表决单元 |
| **`COM-100-031`** | 禁止 | **不得**以户表决；**不得**户主代投；**不得**未经授权的代理投票 |
| **`COM-100-032`** | 必须 | 多人共用设备时，**必须**提供**不同人分别认证**的机制 |
| **`COM-100-033`** | 必须 | 若本人无法自行表决，**必须**有**事先书面授权**；**不得默认代理** |

**一致性测试 T-COM-6**：共用设备演练——两人同一设备表决，**票数必须为 2**。

## 4. 争议入口

| 条号 | 形态 | 条款 |
|---|---|---|
| **`COM-100-070`** | 必须 | 社区**必须**设有可达的争议入口 |
| **`COM-100-071`** | 必须 | 争议**必须先经社区规则**；不决时**升级至协议治理入口** |
| **`COM-100-072`** | 必须 | 协议层**只作规则与账本裁定，不作法律裁判** |
| **`COM-100-073`** | 必须 | 处理时限**必须**事先公示 |
| **`COM-100-034`** | 必须 | 争议处理**必须**以账本与留痕为依据 |

## 4A. 退回通道与不挽留（**本版补入**）

> **源头原句**：
> ## **“每一境必须保留退回通道——冲突后关系降级是正常态不是事故，叙事不得成为单向漏斗。”**

| 条号 | 形态 | 条款 |
|---|---|---|
| **`COM-100-080`** | 必须 | **每一阶段必须保留**退回通道**；关系降级是正常态** |
| **`COM-100-081`** | 必须 | **叙事**不得成为单向漏斗**；不得用“你已经走到这里了”阻止退出** |
| **`COM-100-082`** | **禁止** | **不得**挽留**；不得设置退出阻力（损失已得、降低可见度、拖延处理、需要理由）** |
| **`COM-100-083`** | 必须 | **退出后，本人记录**必须可导出且不受损** |
| **`COM-100-084`** | **必须** | **退出后，社区不得向第三方披露其曾经的位阶或贡献** |

**⚠️ 区别**：**沉淀**是不活跃，**退出**是不再参与——两件事。**

## 5. 信任机制

| 条号 | 形态 | 条款 |
|---|---|---|
| **`COM-100-040`** | 可以 | 社区**可以**建立成员间的协作记录 |
| **`COM-100-041`** | 禁止 | **不得**建立成员间的**信任评分**或**信誉等级** |
| **`COM-100-042`** | 可以 | **可以**记录"**谁与谁协作过**"（事实）与履约结果（事实） |
| **`COM-100-043`** | 禁止 | **不得**将协作记录折算为分值、等级或排名 |

**⚠️ 与 `VAL-400` 一致**：**信任也是镜映，不是评分。**

## 6. 成员权利的最小集（**不得削减**）

| # | 权利 |
|---|---|
| **1** | **知情权**——可查社区规则、公共池余额、表决记录 |
| **2** | **提案权**——任何成员可提 |
| **3** | **表决权**——一人一票 |
| **4** | **陈述权**——被指控时须给陈述机会 |
| **5** | **退出权**——可随时退出；**数据可带走**（依 `ID` 层） |

## 7. 与相邻层的关系

| 相邻层 | 关系 |
|---|---|
| **L1 本体（ID）** | 退出时数据导出**依 ID 层**；社区**不得**扣留 |
| **L3 世界（MOD）** | 模块选用的决定权**在节点**，社区**可以**参与讨论 |
| **L7 意义（VAL）** | 贡献记录**可作议程权依据**，**不得作表决权依据** |
| **治理** | 跨社区争议**升级至治理委员会** |
